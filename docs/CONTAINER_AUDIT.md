# Container prediction audit

The client sends the value returned by `Container.slotClick` in C0E, not always the stack under the cursor. The Java replay in `tools/extract/src/rustmc/extract/DumpContainers.java` exercises chest pickup and merging, successful and blocked shift transfers, number-key moves, and player armor restrictions. `crates/mc-client/tests/data/containers.json` is generated by:

```sh
tools/extract/extract.sh containers furnace_rules enchant_choices
cp golden/containers.json crates/mc-client/tests/data/containers.json
cp golden/furnace_rules.json crates/mc-client/src/furnace_rules.json
cp golden/enchant_choices.json crates/mc-client/tests/data/enchant_choices.json
RUSTMC_REQUIRE_GOLDEN=1 cargo test -p mc-client container::tests
```

The replay uses the real MCP `ContainerChest` and `ContainerPlayer` and checks all slots, cursor, and the packet's clicked stack after each action. It does not constitute coverage of all window types or all click modes.

Known outstanding parity work:

- Furnace shift-click routing, fuel acceptance and bucket limits use rules extracted from Java. Workbench transfer routing, brewing and enchanting slots, and beacon payment rules have Java traces. Anvil input, ordinary transfer routing, and denying result pickup when the player lacks the level have Java traces; repair output callbacks and renaming are still missing. Other specialized containers need their own `transferStackInSlot` and slot validation; beacon power selection still needs implementation. Enchanting choices send C11 and validate levels/lapis, but the animated book, names and tooltips are not yet reproduced.
- Crafting and other result slots have pickup callbacks and can regenerate their contents. Prediction currently does not model those callbacks or repeated shift-clicks.
- Creative middle-click cloning (mode 3), drop key (mode 4), drag splitting (mode 5) and double-click collection (mode 6) have basic Java traces. Shift-double-click and creative drag filling have basic chest traces; drag preview remains unimplemented.
- Exercise NBT, full inventories, damaged items, all armor and crafting cases, and transaction rejection/resynchronization against a server and the Java oracle.
- The creative screen follows a separate code path and is not covered by these survival-container traces.
